# ARMSX2 iOS Build Setup

The iOS Xcode project is generated by CMake. It is not committed to the
repository because Xcode project output contains machine-local build paths and
can become stale quickly.

Swift UI sources live in:

```sh
app/src/main/swift
```

The iOS CMake entry point lives in:

```sh
app/src/main/cpp/CMakeLists.txt
```

## Requirements

- macOS with Xcode installed
- Xcode command line tools selected with `xcode-select`
- CMake 3.16 or newer
- A recursive clone with submodules initialized

## Clone

```sh
git clone --recursive -b armsx2-ios https://github.com/ARMSX2/ARMSX2.git
cd ARMSX2
git submodule update --init --recursive
```

## Generate the Xcode Project

```sh
./scripts/generate-ios-xcode.sh
```

This creates:

```sh
build-ios-xcode/ARMSX2iOS.xcodeproj
```

Open it with:

```sh
open build-ios-xcode/ARMSX2iOS.xcodeproj
```

Use the `ARMSX2iOS` scheme.

## Build an Unsigned IPA

For sideloading or external resigning:

```sh
./scripts/build-ios-ipa.sh
```

The IPA is written to:

```sh
build-ios-xcode/ARMSX2-iOS-unsigned.ipa
```

For a quicker development build, `./scripts/build-ios-ipa.sh --fast` turns off
PCSX2 core LTO and compiles the Swift UI at `-Onone`. It builds in
`build-ios-fast-xcode` and writes `ARMSX2-iOS-development.ipa` there.

## Automatic Signing

If you have an Apple developer team and want Xcode automatic signing, regenerate
with your team and bundle identifier:

```sh
TEAM_ID=YOUR_APPLE_TEAM_ID BUNDLE_ID=com.your.bundle.id ./scripts/generate-ios-xcode.sh
```

Then open the generated project in Xcode and build the `ARMSX2iOS` scheme for an
iOS device.

## Notes

- `build-ios-xcode/` is generated output and should not be committed.
- The build target is iOS device arm64 by default.
- Minimum iOS version is 16.0. The SwiftUI layer uses the swift-perception back-port of the Observation framework on iOS 16, and the helpers in `app/src/main/swift/Models/iOS16Compat.swift` for newer SwiftUI APIs.
- JIT availability depends on how the app is signed and launched. Unsigned IPAs
  may need to be resigned or launched with a compatible sideloading/debug setup.
- Do not rename low-level iOS JIT/runtime symbols unless you are intentionally
  changing that code path. Some internal names are compatibility plumbing and are
  not user-facing branding.

## Building the iOS 16+ IPA in the cloud (no Mac, from a phone)

The `iOS 16+ unsigned IPA` GitHub Actions workflow (`.github/workflows/ios16_ipa.yml`)
builds the app on a GitHub macOS runner and uploads the unsigned IPA as an artifact.

1. Open the repository on github.com in Safari, then **Actions**.
2. Choose **iOS 16+ unsigned IPA**, tap **Run workflow**, pick the `ios16-support`
   branch and confirm. (A push also starts it when the commit message contains
   `[build]`.)
3. When the run is green, open it and download **ARMSX2-iOS16-unsigned-ipa** from the
   **Artifacts** section. If it fails, download **xcodebuild-log** and read the first
   `error:` line; the run page also lists the first errors as annotations.
4. The IPA is unsigned. It has to be re-signed with your own Apple ID or certificate by
   a sideloading tool (AltStore, SideStore, Sideloadly, TrollStore where supported)
   before it installs on a device.

The workflow `iOS Swift check (iOS 16.0)` compiles only the SwiftUI layer against a
16.0 deployment target in a few minutes and is the fastest way to catch API
availability errors.

The iOS 16 build uses the UIKit button press surface for the pad (see
`VirtualPadPressSurfacePolicy`), so several fingers work at once.
